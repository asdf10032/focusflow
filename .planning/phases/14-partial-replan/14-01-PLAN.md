# Plan 14-01: Partial Replan Backend

## Objective

Add a backend endpoint that regenerates plans for the unfinished work in a selected daily plan while preserving execution history.

## Tasks

<task id="14-01-01">
Add backend tests for partial replan.

- Create `tests/test_phase14_partial_replan.py`.
- Cover missing selected plan, feedbacked task exclusion, done/canceled status exclusion, successful persistence, no remaining work, and no schedulable time.
- Use the existing in-memory database and success/error envelope test style.
</task>

<task id="14-01-02">
Support explicit scheduler candidates.

- Update scheduler generation so callers may pass an explicit `Task` list.
- Keep existing `generate` and `reoptimize` behavior unchanged when no explicit candidate list is provided.
- Continue using current blocked-time, energy-template, dependency ordering, scoring, and warning behavior.
</task>

<task id="14-01-03">
Expose `POST /api/v1/schedules/partial-replan`.

- Add request schema `{ date }`.
- Require a selected plan for the date or return `missing_selected_plan`.
- Build remaining candidates from unique selected-plan task IDs in schedule order.
- Exclude missing tasks, same-day execution-log tasks, and tasks whose current status is not `todo` or `in_progress`.
- Return `no_remaining_work` if no candidates remain.
- Return `no_schedulable_time` if no candidate can be placed because no open time remains.
- On success, persist generated plans with existing schedule persistence and clear selected state.
- Never delete or mutate execution logs.
</task>

## Must Haves

- The endpoint uses the existing `status/data/error/meta` envelope.
- Partial replan is selected-plan based, not a full open-task reoptimization.
- Execution logs are preserved in every success and error path.
- Existing schedule endpoints keep their response shape and behavior.
