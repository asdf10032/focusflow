# Plan 14-02: Partial Replan Calendar UI and State

## Objective

Make remaining-work replanning available from Calendar with localized copy, typed API support, and GSD progress tracking.

## Tasks

<task id="14-02-01">
Add typed frontend API support.

- Preserve backend error codes in API failures.
- Add `partialReplanSchedule(date)` returning the existing schedule generation result type.
- Keep existing API client methods compatible with current call sites.
</task>

<task id="14-02-02">
Add Calendar partial replan action.

- Add a button near Reoptimize labeled `Partial Replan` / `重排剩余工作`.
- On success, replace the in-memory schedule with returned plans, default the active plan to balanced when available, clear selected plan state, clear validation state, and show a localized success message.
- On failure, map `missing_selected_plan`, `no_remaining_work`, and `no_schedulable_time` to localized messages.
- Reuse existing plan cards and `selectSchedulePlan` flow for selecting newly generated remaining-work plans.
</task>

<task id="14-02-03">
Extend frontend localization tests.

- Add Chinese and English keys for the partial replan action, success, generic failure, and the three expected error states.
- Extend `tests/test_frontend_i18n.py` to verify the keys are present.
</task>

<task id="14-02-04">
Update GSD phase tracking.

- Mark `PLAN-01`, `PLAN-02`, `PLAN-03`, `PLAN-04`, and `NFR-02` complete.
- Mark Phase 14 complete in `.planning/ROADMAP.md`.
- Update `.planning/STATE.md` so Phase 15 is next.
- Record verification results after the required commands run.
</task>

## Must Haves

- Calendar users can run partial replan without leaving the page.
- Generated remaining-work plans remain selectable through the existing selection endpoint.
- Empty/error states are visible and localized.
- No Phase 15 search or broad empty-state polish is added here.
