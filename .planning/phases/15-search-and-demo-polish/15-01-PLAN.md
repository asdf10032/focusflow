# Plan 15-01: Task Notes and Search Foundation

## Objective

Add optional task notes and deterministic search/filter helpers so Tasks can search title and notes while preserving existing task behavior.

## Context

- `Task` currently has `title` but no task notes field.
- Existing Tasks filtering is client-side for status and project.
- Phase 15 requires search by title and notes and composition with existing filters.
- Exported task data should remain useful outside the app, so new notes data should be included in task export.

## Tasks

<task id="15-01-01">
Add task notes storage and schemas.

- Add Alembic migration `0004_task_notes.py` with nullable `tasks.notes` text column.
- Add `notes: Mapped[str | None]` to `Task`.
- Add optional `notes` to `TaskCreate`, `TaskUpdate`, and `TaskOut` with a max length of 2000 characters.
- Keep existing task create/update/list behavior compatible when `notes` is omitted.
</task>

<task id="15-01-02">
Add backend task search support.

- Extend `GET /api/v1/tasks` with optional `q` query parameter.
- Match `q` case-insensitively against `Task.title` and `Task.notes`.
- Compose `q` with existing `status` and `project_id` filters.
- Preserve current ordering by newest task first.
- Treat blank or whitespace-only `q` as no search filter.
</task>

<task id="15-01-03">
Update task export and demo seed data.

- Include `notes` in task JSON export.
- Seed realistic notes for demo tasks in `demo_data.py`.
- Keep demo seeding repeatable and non-destructive.
</task>

<task id="15-01-04">
Add frontend helper and API types.

- Add `notes` to frontend `Task` and `TaskPayload`.
- Add optional `q`, `status`, and `project_id` parameters to `listTasks`.
- Add `frontend/src/lib/taskView.ts` helper for task filtering/search display logic:
  - normalize search text;
  - match title or notes;
  - compose search, status, and project filters.
- Cover helpers in `tests/test_frontend_view_helpers.py`.
</task>

<task id="15-01-05">
Add focused backend tests.

- Add `tests/test_phase15_task_search.py`.
- Cover create/update/list with notes.
- Cover search by title.
- Cover search by notes.
- Cover search combined with status and project filters.
- Cover task export includes notes.
</task>

## Must Haves

- Existing clients can continue creating tasks without notes.
- Search behavior is deterministic, local, and case-insensitive.
- Search does not introduce external dependencies.
- Migration is additive and nullable.
