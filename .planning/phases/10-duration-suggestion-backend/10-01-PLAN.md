# Phase 10 / Plan 10-01: Snapshot Context and Suggestion API

## Objective

Add the backend data and API foundation for v1.2 duration suggestions.

## Context

- Phase 6 added durable `execution_logs`.
- Existing logs snapshot task title and estimated minutes.
- Phase 10 needs suggestions from durable snapshots rather than mutable current task fields.
- Phase 10 requirements are `DSUG-01`, `DSUG-02`, `LERN-01`, `LERN-02`, and `NFR-01`.

## Implementation Steps

### 1. Extend Execution Log Context

- Add Alembic migration `0003_execution_log_context.py`.
- Add nullable `task_project_id_snapshot` and `cognitive_load_snapshot` columns.
- Update the SQLAlchemy `ExecutionLog` model.
- Update execution feedback creation to snapshot `task.project_id` and `task.cognitive_load`.
- Preserve existing feedback response shape and status behavior.

### 2. Add Suggestion Schemas and Service

- Add request/response schemas for duration suggestions.
- Add a small deterministic service that:
  - reads only completed execution logs with non-null `actual_minutes`;
  - matches by normalized task title similarity;
  - uses project/load snapshot matches to choose confidence and reason code;
  - returns median actual minutes rounded to the nearest five minutes;
  - clamps suggested minutes to 1-480;
  - returns fallback suggestions when no useful history exists.

### 3. Expose API

- Add `POST /api/v1/ai/suggest-duration`.
- Return the existing `status/data/error/meta` success envelope.
- Do not mutate tasks or logs from this endpoint.
- Keep parse-task behavior unchanged.

## Verification

- New Phase 10 tests cover history suggestions, fallback behavior, ignored logs, snapshot stability, validation, and feedback snapshots.
- Existing Phase 6 feedback/history tests continue passing.
