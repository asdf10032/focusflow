# Plan 13-02: Export UI Controls and Phase State

## Objective

Make the new export APIs usable from the existing frontend with localized copy, browser downloads, visible error states, and GSD phase completion tracking.

## Context

- `frontend/src/lib/api.ts` already centralizes typed API calls through `requestJson`.
- `frontend/src/lib/i18n.ts` keeps the lightweight bilingual dictionary and helper functions.
- Tasks and Daily Review are the natural Phase 13 UI surfaces:
  - Tasks should export task JSON.
  - Daily Review should export review CSV and execution history JSON for the selected date.
- Range export can remain API-first in Phase 13 if adding range UI would complicate the surface; single selected-date UI is enough for `EXP-04`.
- Phase 15 will handle broader empty-state polish, so Phase 13 should only add export-specific empty/error messages.

## Tasks

<task id="13-02-01">
Add typed frontend export client methods.

- Update `frontend/src/lib/api.ts` with export response types:
  - `ExportPayload`;
  - `ExportDateRange`.
- Add methods:
  - `exportTasks()`;
  - `exportExecutionHistory(params)`;
  - `exportDailyReview(params)`.
- Encode `date`, `start_date`, and `end_date` query params safely.
- Keep existing API client behavior unchanged for non-export endpoints.
</task>

<task id="13-02-02">
Add browser download helper.

- Add a small helper in an existing frontend utility location or inside the relevant page if narrower is cleaner.
- Convert API export payloads into `Blob` downloads using:
  - payload `content`;
  - payload `content_type`;
  - payload `filename`.
- Revoke generated object URLs after triggering the download.
- Keep helper testable without depending on a real browser download if it is placed in a shared helper file.
</task>

<task id="13-02-03">
Add localized export controls.

- Update `frontend/src/lib/i18n.ts` with Chinese and English keys for:
  - export section labels;
  - export buttons;
  - export success messages;
  - export failure messages;
  - no-data/export-empty guidance.
- Add task JSON export control to `frontend/src/pages/Tasks.tsx`.
- Add Daily Review CSV export and execution history JSON export controls to `frontend/src/pages/DailyReview.tsx`.
- Disable controls while the export request is running.
- Show visible success/failure feedback after export attempts.
- Do not add an import/restore UI.
</task>

<task id="13-02-04">
Extend frontend tests.

- Update `tests/test_frontend_i18n.py` to assert all new export keys exist in Chinese and English.
- If a shared download/query helper is created, extend `tests/test_frontend_view_helpers.py` or add a focused helper test to cover stable query construction and filename usage.
- Keep existing helper and i18n tests passing.
</task>

<task id="13-02-05">
Update GSD phase tracking after implementation.

- Create `13-01-SUMMARY.md` with:
  - backend export API summary;
  - frontend export UI summary;
  - tests/build commands actually run;
  - any manual sanity notes.
- Mark `EXP-01`, `EXP-02`, `EXP-03`, `EXP-04`, and `NFR-01` complete in `.planning/REQUIREMENTS.md`.
- Mark Phase 13 complete in `.planning/ROADMAP.md`.
- Update `.planning/STATE.md` so Phase 14 is the next phase.
- Do not archive the milestone in Phase 13.
</task>

## Must Haves

- Export controls are practical and localized without crowding existing task/review workflows.
- Browser downloads use filenames and content types from the backend.
- Frontend errors are visible and do not clear the underlying page data.
- GSD status is updated only after backend tests, frontend helper/i18n tests, compile checks, and frontend build pass.
