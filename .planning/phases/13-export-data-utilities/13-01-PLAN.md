# Plan 13-01: Export API Foundation

## Objective

Add deterministic, read-only export APIs for tasks, execution history, and Daily Review data while preserving the existing success envelope convention.

## Context

- Existing API responses use `status/data/error/meta` envelopes through `backend.app.core.response.success`.
- Tasks are listed from `backend/app/api/v1/endpoints/tasks.py`.
- Execution history/progress/review logic lives in `backend/app/api/v1/endpoints/execution.py`.
- Daily Review currently computes summary and item variance in endpoint helper functions.
- Phase 13 requires export only; import/restore, cloud sync, and third-party formats are out of scope.
- CSV should not be returned as a raw response because `NFR-01` requires the existing success envelope.

## Tasks

<task id="13-01-01">
Define export schemas and response shape.

- Add `backend/app/schemas/export.py`.
- Define a reusable export response schema with:
  - `filename`;
  - `content_type`;
  - `content`;
  - optional `record_count`.
- Keep response payloads JSON-serializable and compatible with the existing success envelope.
- Use deterministic filenames:
  - `focusflow-tasks.json`;
  - `focusflow-execution-history-YYYY-MM-DD.json` or `focusflow-execution-history-YYYY-MM-DD-to-YYYY-MM-DD.json`;
  - `focusflow-daily-review-YYYY-MM-DD.csv` or `focusflow-daily-review-YYYY-MM-DD-to-YYYY-MM-DD.csv`.
</task>

<task id="13-01-02">
Create export data service.

- Add `backend/app/services/export_data.py`.
- Implement read-only helpers for:
  - task JSON export;
  - execution history JSON export;
  - Daily Review CSV export.
- For task JSON, include stable task fields from `TaskOut` and project context when available:
  - `project_id`;
  - `project_name`;
  - `project_priority`.
- For execution history JSON, include durable execution log snapshot fields:
  - `task_id`;
  - `task_title_snapshot`;
  - `estimated_minutes_snapshot`;
  - `task_project_id_snapshot`;
  - `cognitive_load_snapshot`;
  - `date`;
  - `status`;
  - `actual_minutes`;
  - `note`;
  - `created_at`.
- For Daily Review CSV, include one row per execution log and stable columns:
  - `date`;
  - `task_id`;
  - `task_title`;
  - `status`;
  - `estimated_minutes`;
  - `actual_minutes`;
  - `estimate_variance_minutes`;
  - `note`.
- Support inclusive date range filtering with `date`, or `start_date` and `end_date`.
- Validate that `start_date <= end_date`; return an existing `AppError` shape for invalid ranges.
- Use Python stdlib `csv` and `io.StringIO`; do not add a dependency.
</task>

<task id="13-01-03">
Expose export endpoints.

- Add `backend/app/api/v1/endpoints/exports.py`.
- Register the router in `backend/app/main.py`.
- Add endpoints:
  - `GET /api/v1/exports/tasks`
  - `GET /api/v1/exports/execution-history?date=YYYY-MM-DD`
  - `GET /api/v1/exports/execution-history?start_date=YYYY-MM-DD&end_date=YYYY-MM-DD`
  - `GET /api/v1/exports/daily-review?date=YYYY-MM-DD`
  - `GET /api/v1/exports/daily-review?start_date=YYYY-MM-DD&end_date=YYYY-MM-DD`
- Return `success(export_payload)` for every successful response.
- Do not mutate tasks, projects, schedule plans, or execution logs.
- Keep endpoints available under the existing `/api/v1` prefix.
</task>

<task id="13-01-04">
Add backend export tests.

- Add `tests/test_phase13_exports.py`.
- Use the existing isolated in-memory database/TestClient pattern from Phase 6/7 tests.
- Cover:
  - task export returns success envelope, deterministic filename, JSON content, and project context;
  - execution history export filters by single date;
  - execution history export filters by inclusive date range;
  - Daily Review CSV export includes stable headers and estimate variance;
  - invalid date range returns an error envelope and does not mutate data.
- Keep tests independent of frontend behavior.
</task>

## Must Haves

- Every export endpoint is read-only.
- JSON and CSV output is deterministic enough for tests and demos.
- All backend responses use the existing success/error envelope.
- Date-range filtering is inclusive and validated.
- No migration or new dependency is introduced.
