# Plan 17-01: Weekly Review API Client and View Helpers

## Objective

Expose the Phase 16 weekly-review endpoint to the frontend and add deterministic helper functions for week navigation, labels, and comparison formatting.

## Context

- Phase 16 added `GET /api/v1/execution/weekly-review?date=YYYY-MM-DD`.
- `DailyReview.tsx` already consumes `getExecutionReview(date)` and local formatting helpers.
- Frontend helper tests already transpile TypeScript helper modules through Node.

## Tasks

<task id="17-01-01">
Add weekly review API types and client method.

- Add `WeeklyReviewSummary`, `WeeklyReviewDay`, `WeeklyReviewComparisonDeltas`, `WeeklyReviewComparison`, and `WeeklyReview` types to `frontend/src/lib/api.ts`.
- Reuse `ExecutionReviewItem` for weekly day items.
- Add `getWeeklyExecutionReview(date: string): Promise<WeeklyReview>`.
- Keep existing daily review API types and functions unchanged.
</task>

<task id="17-01-02">
Add weekly review view helpers.

- Create `frontend/src/lib/reviewView.ts`.
- Add `formatMinutesValue(value: number | null): string`.
- Add `formatVarianceValue(value: number | null): string`, preserving `+N` for positive values and a fallback dash for null.
- Add `formatCompletionRate(value: number): string` using whole percentages.
- Add `shiftDateByDays(date: string, days: number): string` for date-only navigation.
- Add `formatWeekRange(weekStart: string, weekEnd: string): string` as `YYYY-MM-DD - YYYY-MM-DD`.
- Add `formatDeltaValue(value: number | null, suffix?: string): string` with `+` for positive numbers and dash for null.
</task>

<task id="17-01-03">
Add helper tests.

- Extend `tests/test_frontend_view_helpers.py` to cover weekly helper output.
- Cover null minutes/variance, positive/negative variance, completion rate, previous/next week date shifting, week range formatting, and delta formatting.
- Use the same Node/TypeScript transpile style as existing frontend helper tests.
</task>

## Must Haves

- Helper behavior is deterministic and timezone-safe for date-only values.
- No UI changes are required in this plan.
- The API client still throws existing `ApiError` behavior for failed envelopes.
