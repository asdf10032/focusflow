# Plan 17-02: Daily Review Weekly View UI

## Objective

Add the weekly review experience inside Daily Review while preserving existing daily review history and export flows.

## Context

- Daily Review currently renders a date picker, refresh button, history/review export buttons, daily summary metrics, and daily log items.
- Phase 17 should add a view switch, not a new route or nav item.
- Weekly export is future scope; existing daily exports remain daily-mode controls.

## Tasks

<task id="17-02-01">
Add daily/weekly view state and loading.

- Add `viewMode: "daily" | "weekly"` state in `DailyReview.tsx`.
- Keep the existing `date` state as the selected anchor date for both modes.
- Daily mode calls `getExecutionReview(date)`.
- Weekly mode calls `getWeeklyExecutionReview(date)`.
- Refresh reloads the active mode.
- Changing the date reloads only when the user presses refresh, matching current daily behavior.
</task>

<task id="17-02-02">
Add weekly navigation controls.

- Add a segmented control near the header for Daily and Weekly.
- In weekly mode, show previous-week and next-week buttons using `shiftDateByDays(date, -7)` and `shiftDateByDays(date, 7)`.
- Show the selected week range from the weekly response.
- Keep daily export buttons visible and functional in daily mode; hide or visually separate them in weekly mode so users do not mistake them for weekly exports.
</task>

<task id="17-02-03">
Render weekly metrics and comparison.

- Render metric cards for completion rate, actual minutes, estimate variance, logged count, completed count, and skipped/incomplete count.
- Render previous-week deltas for completion rate, actual minutes, and estimate variance when `comparison.available` is true.
- Render localized comparison-unavailable copy when `comparison.available` is false.
- Use helper functions from `reviewView.ts` for rate, variance, minutes, week range, and deltas.
</task>

<task id="17-02-04">
Render seven-day breakdown.

- Render all seven `weeklyReview.days` entries in ascending order.
- Each day shows date, completion rate, actual minutes, variance, and logged count.
- If a day has items, list compact task rows with outcome, estimate, actual, variance, and note.
- If a day has no items, show localized empty-day copy.
- Keep layout responsive and avoid nested cards inside cards.
</task>

<task id="17-02-05">
Add bilingual copy and tests.

- Add Chinese and English i18n keys for:
  - daily/weekly view labels;
  - previous week and next week actions;
  - weekly range label;
  - weekly summary title;
  - logged count;
  - previous-week comparison title;
  - comparison unavailable copy;
  - daily breakdown title;
  - empty week and empty day copy.
- Extend `tests/test_frontend_i18n.py` with a Phase 17 weekly review key test.
- Keep existing i18n tests passing.
</task>

<task id="17-02-06">
Run verification and update GSD state.

- Run frontend helper/i18n tests.
- Run `npm.cmd run build` from `frontend/`.
- Update `.planning/REQUIREMENTS.md`, `.planning/ROADMAP.md`, and `.planning/STATE.md` after execution to mark Phase 17 complete and Phase 18 next.
</task>

## Must Haves

- Existing daily review history and export behavior remains intact.
- Weekly view uses the Phase 16 success-envelope endpoint through the typed API client.
- Weekly UI is localized for both supported languages.
- No backend changes or migrations are required.
