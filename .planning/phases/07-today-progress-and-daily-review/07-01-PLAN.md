# 07-01 Plan: Progress and Review Backend APIs

## Goal

Expose aggregation endpoints that turn selected plans and execution logs into practical Today progress and Daily Review data.

## Scope

- Add execution review schemas for progress metrics, daily review summaries, and review items.
- Add `GET /api/v1/execution/progress?date=YYYY-MM-DD`.
- Add `GET /api/v1/execution/review?date=YYYY-MM-DD`.
- Keep all responses inside the existing success envelope.
- Use the selected schedule plan for planned work and planned duration.
- Use `execution_logs` for completed, skipped, incomplete, canceled outcomes and actual duration.
- Preserve empty selected-plan behavior as a successful response with empty metrics instead of an error.

## Implementation Notes

- Completion rate should be deterministic and easy to display: `completed_count / planned_count`, returning `0` when `planned_count` is `0`.
- Treat history statuses as review outcomes:
  - `done` counts as completed.
  - `skipped`, `incomplete`, and `canceled` count as not completed.
- Planned duration for review should come from the selected plan's scheduled items when available.
- Estimate variance should be `actual_minutes - estimated_minutes_snapshot` for logged items with actual minutes.
- If multiple feedback logs exist for the same task on the same date, keep all logs in the review list but derive summary counts from the latest log per task to avoid double-counting status outcomes.
- Do not introduce new database tables or migrations in Phase 7.
