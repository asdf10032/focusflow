# 07-02 Plan: Today Metrics and Daily Review Frontend

## Goal

Make execution history visible in the UI by adding Today progress metrics and a date-filtered Daily Review flow.

## Scope

- Add typed frontend API client methods for `execution/progress` and `execution/review`.
- Extend the Today page to show planned count, completed count, skipped/incomplete count, and completion rate.
- Refresh Today metrics after feedback submission.
- Add a Daily Review page and nav entry.
- Daily Review must support date selection and show:
  - work outcomes by status,
  - planned duration,
  - actual duration,
  - estimate variance,
  - per-item estimated vs actual duration when available.
- Add Chinese and English copy for all new UI text using the existing i18n module.
- Keep empty states clear when no plan or no history exists.

## Requirements

- PROG-01
- PROG-02
- PROG-03
- EST-01
- EST-02
- REV-01
- REV-02
- FILT-03

## Implementation Notes

- Reuse the existing `Today.tsx` layout style and compact operational UI tone.
- Prefer simple metric tiles or compact bands, not nested cards.
- Daily Review should be a practical work surface, not a marketing page.
- Feedback controls can remain on Today; Daily Review is read-only in Phase 7.
- Use existing `getStatusLabel`, `getPlanTypeLabel`, and translation patterns.
- Extend API types rather than using `unknown` payloads.

## Tests

- Extend `tests/test_frontend_i18n.py` with Phase 7 translation keys.
- Extend frontend helper tests only if new pure formatting helpers are added.
- Run `npm.cmd run build`.
