# Plan 11-02: Tasks Page Suggestion Flow

## Objective

Wire duration suggestions into the existing Tasks form and Quick Parse flow without automatically overwriting user estimates.

## Context

- `Tasks.tsx` keeps form state locally and already supports Quick Parse.
- Phase 11 should keep the page utilitarian and consistent with the existing form/card styling.
- Suggestion acceptance is explicit: display first, update minutes only when the user clicks accept.

## Tasks

<task id="11-02-01">
Add suggestion state to Tasks page.

- Track current `DurationSuggestion | null`.
- Track suggestion loading state separately from task save/load if needed, or reuse `loading` only if the UI stays clear.
- Clear stale suggestions when:
  - user starts editing another task;
  - user cancels editing;
  - task is saved;
  - parsed draft or manual input materially changes title, minutes, or cognitive load.
</task>

<task id="11-02-02">
Add manual request and display controls.

- Add a compact suggestion panel near the minutes/load fields, not nested inside another card.
- Add a "Suggest duration" button that calls `suggestTaskDuration` with:
  - trimmed form title;
  - numeric `cognitive_load` when valid;
  - numeric `estimated_minutes` when valid;
  - current task/project id only if the form already carries a project value in this UI.
- If title is missing, show the existing title-required message or a new localized suggestion message.
- Display suggested minutes, confidence, sample count, source, and localized reason.
- Keep backend `reason` available as fallback when reason code is unknown.
</task>

<task id="11-02-03">
Add explicit accept/manual override behavior.

- Add an "Use suggestion" button visible only when a suggestion exists.
- Clicking it sets `form.estimated_minutes` to `suggested_minutes`.
- After accepting, user can still type a different minutes value.
- Do not change `title`, `cognitive_load`, due date, split settings, or status when accepting.
</task>

<task id="11-02-04">
Extend Quick Parse flow with suggestion metadata.

- After `parseTaskDraft(text)` returns, set the form from the draft as today.
- Then call `suggestTaskDuration` using the parsed title, parsed cognitive load, and parsed estimate.
- Show suggestion metadata in the same panel.
- If suggestion fetch fails after parse succeeds, keep the parsed form and show a localized suggestion failure message rather than failing the whole parse.
</task>

<task id="11-02-05">
Verify and update GSD state.

- Run i18n/helper tests and frontend build.
- Add `11-01-SUMMARY.md` with implementation and verification notes.
- Mark `DSUG-03`, `DSUG-04`, and `UX-01` complete in `.planning/REQUIREMENTS.md`.
- Mark Phase 11 complete in `.planning/ROADMAP.md`.
- Update `.planning/STATE.md` to route to `$gsd-plan-phase 12 --skip-research`.
</task>

## Must Haves

- Suggestions do not overwrite estimates unless accepted.
- Parse-task suggestions do not break successful parsing if the suggestion request fails.
- New UI copy is fully bilingual.
- No backend migration or API shape change is introduced in Phase 11.
