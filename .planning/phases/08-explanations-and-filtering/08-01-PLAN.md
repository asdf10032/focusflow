# 08-01 Plan: Deterministic Schedule Explanations

## Goal

Make generated schedules easier to understand by adding deterministic plan summaries, risk explanations, and unplaced-task reasons.

## Scope

- Extend schedule schemas with explanation fields while preserving the existing success envelope:
  - plan-level `summary`
  - plan-level `risk_explanation`
  - response-level structured `unplaced_reasons`
- Generate explanations locally from existing scheduler inputs and outputs.
- Keep generate, reoptimize, demo seed, and persistence response shapes backward-compatible for existing fields.
- Add backend tests for explanation text, high-risk blocked-day reasons, and no external network/AI dependency.

## Requirements

- EXPL-01
- EXPL-02
- NFR-03

## Implementation Notes

- Explanation text should be deterministic and short enough to display in Calendar/Today.
- Plan summaries can use existing metrics such as placed task count, item count, score, risk level, and plan type.
- Unplaced reasons should be structured objects with `task_id`, `reason`, and `message`.
- For Phase 8 MVP, acceptable reasons include:
  - no available slot capacity,
  - dependency cycle surfaced through existing scheduler error path,
  - blocked day or blocked time pressure inferred from unavailable slots.
- Avoid database migrations unless a persisted model column is truly required; prefer generating explanations with schedule response data first.

## Tests

- Add `tests/test_phase8_explanations.py`.
- Assert generated plans include non-empty `summary` and `risk_explanation`.
- Assert unplaced tasks include structured reasons.
- Assert full-day blocked schedules produce high-risk explanation and capacity reason.
- Assert existing Phase 4 schedule API tests keep passing.
