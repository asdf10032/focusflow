# 08-02 Plan: Frontend Explanations and Task Filters

## Goal

Expose the new schedule explanation data in the UI and make the growing task list easier to navigate.

## Scope

- Extend frontend API types for schedule summaries, risk explanations, and unplaced reasons.
- Display plan summaries and risk explanations in Calendar.
- Display unplaced task reasons near the existing unplaced/warnings section.
- Add status filter controls to the Tasks page.
- Add project filter controls to the Tasks page when project data is available.
- Add Chinese and English copy for Phase 8 text.
- Keep Today and Daily Review behavior unchanged except where they benefit from already-selected plan summaries.

## Requirements

- EXPL-03
- FILT-01
- FILT-02
- NFR-03

## Implementation Notes

- Reuse existing operational UI patterns: compact controls, simple metric/explanation bands, no marketing layout.
- Status filtering can default to `all` and use the existing task status labels.
- Project filtering can default to `all`; tasks with no project should remain visible when `all` is selected.
- If the frontend currently lacks a project list API client, add a typed client method and keep the UI resilient when projects cannot be loaded.
- Avoid nested cards and avoid adding any external UI or AI dependency.

## Tests

- Extend `tests/test_frontend_i18n.py` for Phase 8 labels.
- Extend frontend helper tests only if pure filter/format helpers are extracted.
- Run `npm.cmd run build`.

## Verification

- `python -m pytest tests/test_frontend_i18n.py tests/test_frontend_view_helpers.py -q -p no:cacheprovider`
