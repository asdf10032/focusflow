# Plan 12-01: Demo Seed History and Smoke Coverage

## Objective

Make the local demo data prove both sides of v1.2 duration suggestions: confident history-based suggestions and deterministic fallback suggestions.

## Context

- Phase 5 introduced repeatable, non-destructive demo seeding.
- Phase 9 extended the demo loop with execution review history.
- Phase 10 added duration suggestions from execution log snapshots.
- Phase 11 surfaces suggestions in Tasks, but the task form does not currently expose `project_id`; API smoke coverage should still verify the high-confidence project/load path.
- Existing `demo_data.py` upserts tasks and execution logs; verify and, if needed, update it so seeded execution logs include the Phase 10 snapshot fields.

## Tasks

<task id="12-01-01">
Make seeded execution history suggestion-ready.

- Update `backend/app/services/seeds/demo_data.py` so every seeded execution log snapshots:
  - `task_title_snapshot`;
  - `estimated_minutes_snapshot`;
  - `task_project_id_snapshot`;
  - `cognitive_load_snapshot`.
- Keep `task_id` as a plain integer and preserve existing history behavior.
- Keep seed behavior repeatable by upserting existing demo logs instead of appending duplicates on every run.
- Keep seed behavior non-destructive: do not wipe user data and do not introduce reset behavior in this phase.
</task>

<task id="12-01-02">
Ensure demo data demonstrates both learned and fallback duration paths.

- Use the existing demo project and task set unless a small additional demo task is clearly needed.
- Ensure at least one seeded `done` execution log has `actual_minutes` and snapshots that can produce a history-based suggestion when calling `/api/v1/ai/suggest-duration` with matching title, `project_id`, and cognitive load.
- Ensure fallback can be demonstrated by calling the same endpoint with a novel title and either current estimate or cognitive-load band.
- If useful, include explicit example payloads in the seed return value for documentation/tests, but do not change any public API response shapes.
</task>

<task id="12-01-03">
Extend smoke coverage.

- Extend `tests/test_demo_flow.py` rather than creating a broad new suite.
- Keep the isolated in-memory database fixture.
- Assert seeding twice remains repeatable:
  - task count stays stable;
  - blocked time count stays stable;
  - schedule plan count stays stable;
  - execution log count stays stable.
- Assert seeded execution logs include project and cognitive-load snapshots.
- Assert `/api/v1/ai/suggest-duration` returns a success envelope for a history-based seeded suggestion:
  - `source == "history"`;
  - `confidence == "high"`;
  - `sample_count >= 1`.
- Assert `/api/v1/ai/suggest-duration` returns a success envelope for a fallback suggestion:
  - `source == "fallback"`;
  - deterministic suggested minutes from current estimate or cognitive load.
- Preserve existing assertions for Today, progress, review, history, feedback, schedule generation, and parse-task.
</task>

## Must Haves

- Demo seeding remains safe to run repeatedly in a local database.
- Seeded history proves Phase 10 snapshot learning, not mutable current task fields.
- Smoke coverage uses standard success envelopes for the suggestion endpoint.
- No migration, frontend feature, scheduler scoring, or external dependency is added.
