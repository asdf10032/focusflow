# Requirements Archive: v1.0 MVP

**Archived:** 2026-04-27
**Status:** SHIPPED

The current planning directory intentionally has no active `REQUIREMENTS.md`; the next milestone should create fresh requirements through `$gsd-new-milestone`.

## Version Scope

- V1.0: local demoable MVP for the complete scheduling loop.

## Completed Functional Requirements

- [x] REQ-PROJ-CRUD: User can create/query projects with priority.
- [x] REQ-TASK-CRUD: User can create, read, update, and delete tasks with dependencies, deadlines, split settings, and status.
- [x] REQ-ENERGY: System provides weekday/weekend energy templates with 48-slot curves.
- [x] REQ-BLOCKED: User can configure blocked time for classes, sleep, or custom unavailable periods.
- [x] REQ-SCHEDULE-3PLANS: Schedule generation returns conservative, balanced, and aggressive daily plans.
- [x] REQ-SCHEDULE-SELECT: User can select a plan and later read selected state.
- [x] REQ-SCHEDULE-VALIDATE: Validate-move detects overlap and blocked-time conflicts.
- [x] REQ-SCHEDULE-REOPT: Reoptimization regenerates same-day plans and clears stale selection.
- [x] REQ-EXECUTION: Today page/API shows selected work and accepts feedback.
- [x] REQ-AI-PARSE: Local deterministic parse-task endpoint returns structured task drafts.
- [x] REQ-CALENDAR-VIEW: Calendar page displays generated task blocks and switches plan variants.
- [x] REQ-DEFAULT-SEEDS: Default energy templates can be seeded.

## Completed Nonfunctional Requirements

- [x] NFR-API: Endpoints use the `status/data/error/meta` success envelope.
- [x] NFR-VALIDATION: Backend uses typed schemas and validation for API payloads.
- [x] NFR-TEST: Phase 1-5 tests and smoke coverage verify the MVP loop.
- [x] NFR-UX: Frontend supports bilingual copy, clear calendar controls, Today flow, and documented demo path.
